## 7. Ablation on Run D logs

Computed offline from Run D's logs — no new runs (`analysis/replay.py`, applied per run, pooled over the 5). Detection uses the same definition as the full evaluation (flow level, or its host pair while active, >= CLONE).

- **(a) IF only** — the logged per-window raw IF levels (flow and host-pair models) replayed through the controller's own hysteresis (`controller/policy.FlowPolicy`), every DPI confirmation ignored; no flow-head clones (N = 0); adaptive sampling kept (it feeds the IF's payload-entropy feature, Decision C).
- **(b) DPI-head only** — no IF: raw level NORMAL every window; each logged DPI confirmation attributable to a flow-head clone (clone_reason 4, or 3 under a host rule that a DPI-head escalation installed) forces the flow, and for syn/null scans its host pair, to DROP (the controller's own action in Run D), at the poll that processes it, then de-escalates by the same hysteresis; head clones kept (N = 3); no sampling. Confirmations used: reason 3 dropped: 98, reason 3 kept: 142, reason 4 kept: 1141.
- **(c) full system** — the logged run as it happened (`analysis/evaluate.py`; inspection from the data-plane counters).

**How far to trust (a) and (b).**
- *Level replay:* on flow slots and host pairs that no DPI action ever touched, the IF-only replay reproduces the logged level on 99.73% of flow rows and 100.00% of pair rows, and replaying the logged levels reproduces the full system's per-flow detections exactly. Of the 17 benign flows (b) flags, 16 are also flagged by the full system (credited there to IF-flow 14, DPI-head 2); the rest were flagged only in the replay, whose de-escalation and timing differ from the logged run's, and (b) detects no attack flow the full system missed.
- *Inspection estimate:* the clone estimator, run on the full system's logged levels, matches the measured data-plane counters to within +5.1% to +17.7% of total clones per run (forwarded packets within 1.53%; dropped packets 1359 estimated vs 543 measured over the 5 runs); it overestimates drops because it treats a rule as in force from the start of the next poll window, while the controller installs it at the end of the poll that decided it (up to a few hundred ms later) — chiefly a source drop landing as a benign iperf3 flow starts, most of whose first-window packets pass before the rule is in place; (a) and (b) use the same estimator. In (a) nothing is dropped (the IF never sets DROP), so packets the full system dropped count as forwarded there.
- *Not captured:* the traffic, the IF scores and DPI's own decisions are the logged ones. With a different clone stream DPI could decide differently — e.g. without sampled iperf3 clones, its syn-scan ratio rule (suppressed by them in Run C, see RESULTS.md) might fire more often in (b). (b) is therefore a lower bound on what a DPI-head-only system would confirm, not an exact replay.

**p5 = 0 in every run** (to floating-point precision) because the MONITOR threshold coincides with sklearn's `contamination = 0.05` boundary: `IsolationForest.decision_function` is the raw score minus `offset_`, and `offset_` is set to the 5th percentile of the training scores when contamination = 0.05. The warm-up 5th percentile of `decision_function` is therefore 0 by construction — the MONITOR threshold is exactly the boundary sklearn itself would use to call a sample an outlier. The CLONE threshold (p1) is the only one that varies by run.
